SPÉCIFICATIONS TECHNIQUES DE L'ARCHITECTURE

Structure modulaire découplée en crates Rust indépendantes.

01 / PROTOCOLE VIDÉO UDP (DROP-ON-LATE)

Zéro Accumulation de Latence

Les flux TCP classiques (RTMP, RTSP sur TCP) provoquent des gels d'image puis une avance rapide dès qu'un paquet est réémis. Le réassembleur UDP OpenCam élimine immédiatement toute trame partielle dont la séquence est dépassée. Le flux reste calé en temps réel avec une latence inférieure à 20 millisecondes sur réseau local Wi-Fi 5GHz.

crate : crates/core-protocol/src/packet.rs
02 / CADRAGE CENTER STAGE & DISTANCE AUTO-ZOOM

Filtre Exponentiel du 2nd Degré

Le module de suivi analyse la position normalisée de la boîte englobante du visage et sa hauteur relative. L'auto-zoom compense automatiquement le recul de l'intervenant pour maintenir un plan stable (visage, buste ou plan large) avec un amorti de mouvement réglable sans à-coups.

crate : crates/camera-capture/src/face_tracking.rs
03 / SORTIE SYSTÈME LINUX & WINDOWS

Direct Kernel Loopback & MF Driver

Sous Linux, les trames décodées sont converties en YUYV 4:2:2 via instructions SIMD rapides et écrites directement dans le descripteur ioctl de /dev/videoX. Sous Windows, l'injection s'effectue via l'interface Virtual Camera de Media Foundation.

crate : crates/vcam-sink/src/linux.rs
04 / CAPTURE MOBILE NATIVE SANS SURCOUCHE

Android Camera2 NDK & iOS AVFoundation

Aucun framework hybride lourd (Flutter, React Native ou Electron). Le code mobile compile directement en binaire natif via cargo-ndk (Android) et cargo-apple (iOS) avec encodage matériel direct pour minimiser l'échauffement de la batterie.

crate : crates/camera-capture/src/android.rs
